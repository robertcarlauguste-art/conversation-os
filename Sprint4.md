# Sprint 4: Executive Command Center

## Outcome

Sprint 4 turns the dashboard from a set of counters into an operational command
center. An agent can see what failed, who needs contact, which commitments are
open, what recently changed, and request a concise AI briefing without leaving
the page.

## Delivered

- One unified `GET /api/v1/dashboard` response for the complete dashboard.
- Overview counts, recent clients, recent conversations, alerts, and follow-ups.
- Deterministic executive priorities and explainable contact recommendations.
- On-demand AI morning briefing with graceful fallback behavior.
- Durable follow-up actions: record contact, snooze, and complete.
- Open action-item queue with duplicate-source grouping and bulk completion.
- Reopening of completed action items.
- Append-only recent activity for follow-up decisions and recorded contact.
- Responsive Next.js dashboard backed by TanStack Query.
- Interaction tests for record-contact, grouped completion, and reopening.

## Ranking rules

Recommendations are derived from stored data, not generated by the language
model. The follow-up threshold is seven days. A client with no conversation has
a base urgency of 50. A stale client scores `50 + days stale + 5 per open
action`; a recently contacted client with open actions scores `70 + 5 per open
action`. Scores are capped, ties use stable client name/id ordering, and only
the first five recommendations are returned. Failed conversation processing is
ranked ahead of follow-ups because hidden memory can invalidate downstream
advice.

## Operational guardrails

- The AI briefing runs only when requested; core dashboard data is deterministic.
- Follow-up activity is append-only.
- Dashboard queries are bounded. The repository considers up to 100 open action
  items, the UI returns up to 10 grouped next actions and 10 recent activities,
  and recommendations are capped at five.
- Production dependencies are audited as part of the Sprint 4 hardening pass.

## Verification

- Backend unit and integration suite.
- Frontend typecheck, lint, production build, and interaction tests.
- Desktop and mobile browser inspection against the running backend.
- Clean temporary-database migration from an empty database through head.

## Known limitations and Sprint 5 candidates

- Authentication and multi-tenant isolation are not yet implemented.
- Conversation processing remains synchronous and needs a retryable background
  queue before production use.
- Larger queues need cursor pagination and user-configurable filters.
- Client identity resolution still needs stronger corroborating attributes.
- AI briefing quality should gain evaluation fixtures before prompt iteration.
